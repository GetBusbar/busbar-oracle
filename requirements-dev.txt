# The oracle's development dependencies, pinned by version AND by digest.
#
# The oracle decides whether somebody shipped a regression, so its own CI is the boring kind: a
# linter that could change between two runs is one more way a verdict about a product could be a
# verdict about the machine. `pip install --require-hashes -r requirements-dev.txt` refuses to
# install anything whose bytes are not named here, and refuses the whole file if any requirement
# lacks a hash -- so a dependency added without one fails loudly rather than floating.
#
# Every published wheel for the version is listed, not only the one this laptop happens to need:
# pip picks the file matching the platform it is running on, and CI (ubuntu x86_64), a maintainer on
# an arm64 Mac and a contributor on Windows must all be held to the same pin. The sdist is here for
# a platform with no wheel.
#
# Digests are PyPI's own, from https://pypi.org/pypi/ruff/0.8.4/json. To move the pin:
#   curl -sS https://pypi.org/pypi/ruff/<version>/json \
#     | python3 -c 'import json,sys; [print(f["filename"], f["digests"]["sha256"]) for f in json.load(sys.stdin)["urls"]]'
#
# There are no RUNTIME dependencies and there must not be: the oracle has to be able to judge a
# workspace without sharing anything with it. See pyproject.toml's `dependencies = []`.

# PyYAML is a DEV dependency, not a runtime one, and the difference is the whole point.
#
# apply-mutation.py needs it: a boot mutation is applied to the PARSED config document, so the
# recorder can only run mutation cells on a host with PyYAML (record.sh says so out loud -- a
# missing PyYAML is exit 2, "the tool failed", never a named gap). But this package must be
# installable into a venv that shares nothing with the workspace it judges, so `dependencies` in
# pyproject.toml stays empty and PyYAML stays a thing the PRODUCT's environment provides.
#
# It is here because the tool's own CI runs `apply-mutation.py --selftest`, and that self-test owns
# the case that proves the mutation fixture is read out of the product's DATA directory rather than
# from beside the tool -- the defect that turned 232 boot cells into FAIL rows. A case that skips
# itself when an import is missing is a case that reports green over the bug it exists to catch, so
# CI installs the interpreter the recorder needs and the self-test refuses to be skipped.
#
# Digests are PyPI's own, from https://pypi.org/pypi/PyYAML/6.0.2/json, every published file for the
# version, for the reason stated above: CI, a maintainer on an arm64 Mac and a contributor on
# Windows are all held to the same pin.
